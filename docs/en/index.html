02 / ONE PROCESS, SIX STEPSNO BULK CLEANUP

Measure. Understand.
Change with purpose.

Understand before recommending. Assess scope, activation and Project Relevance. Keeping everything can be the right outcome.

  1. 01
    baseline

    Start with your project.

    Agent, version, essential tasks and initial evidence. Detection uses what you provide; otherwise, we ask.

    ⌁
  2. 02
    inventory → context map

    Map what each agent carries.

    WHAT IS IT / WHERE DOES IT LIVE / WHEN IS IT USED. Installed, listed and loaded are different.

    ⊞
  3. 03
    scope → activation → relevance

    Evaluate what belongs here.

    Check Duplication, Conflict, Overlap, Stale and Capability Bloat against the project’s actual needs.

    ≋
  4. 04
    recommendation → one change

    Choose one reversible change.

    Understand evidence, expected impact, dependencies, scope and rollback. You decide and apply it.

    ↗
  5. 05
    before / after → keep / revert

    Measure, test and decide.

    Compare the same measure and test the affected capability in every agent involved. Keep or revert.

    ✓
  6. 06
    report → optional feedback

    Leave with evidence.

    Review results and open questions. Afterwards, choose whether to prepare non-sensitive metrics for manual sharing.

    ≡

WHAT / WHERE / WHEN

A model you can use in every project.

WHAT IS IT?

Skill · Agent · MCP · Plugin · Hook · Rule · Memory

WHERE DOES IT LIVE?

Global / User · Project · Directory · Session

WHEN IS IT USED?

Always · Conditional · Explicit · Disabled · Unknown

Multiple / cross-agent: identify shared sources and conflicting instructions. Keep repetition when another agent needs it. A removal candidate is a recommendation, not an activation state.

05 / NO BLACK BOX

Worth knowing.

Will this reduce my tokens by 87.4%?+

No token-saving percentage has been measured. The historical 87.4% describes never-used skill counts. Tokens, time and money each require their own comparable measurements.

Which agents can I audit?

V1 includes documentary adapters for Claude Code, Codex, Google Antigravity and Cursor, with a Multiple mode. This is architectural support; native installation and full audits in all four hosts still need testing.

Does the coach disable or delete anything on its own?+

During the audit, no: it uses the evidence you provide and you apply changes. The Bootstrap Prompt authorizes installing Context Hygiene itself in this project, subject to host permissions. Optional changes require your authorization.

What do I need to share?+

Share the version, essential tasks and the smallest relevant inventory or screenshot. Hide secrets first. Missing token metrics remain unknown. Host privacy policies still apply. Privacy (PT).

Are audit metrics collected?

Off by default. After the report, you may opt in to prepare non-sensitive numbers, review them and share manually. No collector or automatic sending. Existing website GA4 analytics is separate from audit metrics.
